# User Management — Requirements

## Objective
Establish the first functional capability of Mini E-Commerce: platform User Management.

## Functional requirements
- FR-01 Create a User.
- FR-02 Retrieve a User by ID.
- FR-03 Retrieve all Users.
- FR-04 Update editable User information and roles.
- FR-05 Update User lifecycle status independently.
- FR-06 Replace User roles independently.
- FR-07 Delete a User.

## Business rules
- User ID is generated by the system and immutable.
- `username` is required and unique case-insensitively.
- `firstName` is required.
- `lastName` is required.
- `email` is required, valid, and unique case-insensitively.
- A User must have at least one role.
- Supported roles are `CUSTOMER`, `SELLER`, and `ADMIN`.
- Multiple roles are allowed.
- New Users start with status `ACTIVE`.
- Supported statuses are `ACTIVE` and `INACTIVE`.
- `createdAt` is created once and remains unchanged.
- `updatedAt` changes when mutable state changes.
- During update, a User may retain their own username and email.
- A missing User is reported as not found.

## Out of scope
Authentication, passwords, JWT/OAuth2, Customer/Seller profiles, Product Catalog, Inventory, Cart, Orders, Payments, Notifications, and messaging.
